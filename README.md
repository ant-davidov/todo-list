# My Tasks — Vercel

Список задач с входом по GUID и общей базой Neon PostgreSQL. Можно создать пользователя или войти по существующему коду с другого устройства. Почта и пароль не требуются.

## Публикация

1. Загрузите содержимое этой папки в Git-репозиторий и импортируйте его в Vercel. Если репозиторий содержит несколько проектов, выберите `todo-list` как Root Directory. Если загружена только эта папка, оставьте корень репозитория.
2. Подключите **Neon PostgreSQL** через Vercel Marketplace или создайте базу Neon отдельно. Сохраните строку подключения в переменной **`DATABASE_URL`** для нужных окружений Vercel. Она используется только сервером.
3. Один раз выполните [database/schema.sql](database/schema.sql) в SQL Editor Neon. Альтернатива: задайте `DATABASE_URL` локально и выполните `npm run db:setup`. Повторный запуск сохраняет существующие данные.
4. Запустите Deploy в Vercel. Настройки уже заданы в `vercel.json`: Framework **Other**, Node.js **24.x**, Build Command **`npm run build`**, Output Directory **`dist`**. Команда установки — `npm ci`.
5. На опубликованном сайте создайте пользователя, сохраните GUID, добавьте задачу. В другом браузере выберите «Войти по коду», введите тот же GUID и проверьте список.

Папку `dist` нельзя публиковать отдельно: приложению также нужны функции `api/`, модули `lib/` и подключённая база. Сам сервер `server.cjs` на Vercel не запускается; он нужен только для локальной разработки. При отсутствии базы API возвращает понятную ошибку, а не подменяет серверное хранение локальным.

Текущая публикация в Sites остаётся отдельной версией. Для переноса на Vercel используются файлы этого проекта, а не архив для Sites. `.openai/` исключена из загрузки в Vercel.

## Локальный запуск

Для работы без Neon выполните `npm run dev:local` (или `node server.cjs --local`). Откройте `http://localhost:4173` и нажмите «Создать пользователя». Этот режим хранит задачи в `.local/tasks.json`; они сохраняются после перезагрузки страницы и перезапуска сервера. Код пользователя и задачи опубликованного сайта относятся к отдельной базе и здесь недоступны. Папка `.local` исключена из Git и публикации в Vercel.

Для подключения локального сервера к Neon используйте обычный запуск ниже. Файловое хранилище включается только явным флагом `--local`; опубликованный API по-прежнему требует `DATABASE_URL`.

Требуется Node.js 24.

```sh
npm ci
```

Скопируйте `.env.example` в `.env.local`, задайте настоящую строку `DATABASE_URL`, затем:

```sh
npm run db:setup
npm run dev
```

Адрес по умолчанию: `http://localhost:4173`. Другой порт задаётся переменной `PORT`.

```sh
npm test
npm run build
```

Тесты проверяют сервис с изолированным хранилищем в памяти: создание, вход, разделение пользователей, даты, валидацию и конфликты версий. Для проверки реального подключения нужны настроенная Neon-база и выполненная схема.

## GUID и данные

- GUID создаётся сервером через `crypto.randomUUID()`. Произвольный или неизвестный GUID не создаёт пользователя.
- GUID является секретным кодом доступа. Его обладатель может читать и менять задачи; дополнительного пароля и восстановления через почту нет. Код не передаётся в URL и не записывается в серверные логи. База хранит SHA-256 хеш кода.
- Браузер запоминает код для следующего входа. «Сменить пользователя» очищает текущий вход и открывает форму; данные в базе остаются.
- Задачи, даты и версия списка хранятся в PostgreSQL. В браузере нет постоянной копии серверных задач. Изменения подтверждаются только после успешного ответа сервера; при ошибке введённый текст сохраняется в поле.
- При возврате к вкладке и каждые 30 секунд видимый список обновляется. Устаревшее сохранение получает `409`, обновляет список и предлагает повторить действие. Одновременные изменения не перезаписываются молча.
- Отмена удаления работает в текущей вкладке до перезагрузки. Можно восстановить несколько удалений по очереди.
- До 500 задач на пользователя, до 250 символов на задачу.
- Если на том же адресе остались задачи прежней версии в `localStorage`, доступна кнопка переноса. Она переносит задачи только в выбранный пользователем список; исходные локальные данные сохраняются. Данные другого домена автоматически недоступны: задачи из прежнего Sites-адреса не появятся на Vercel сами.
